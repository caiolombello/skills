# Imagery and provenance

Load when choosing, sourcing, replacing, or reviewing images or footage. Keep
the existing brand, content, privacy, accessibility, and performance constraints.

## Start with available material

Inspect supplied assets and the project's current image usage before designing
around a photograph. Distinguish a file that exists from an asset promised for
later. Match the image to its job: showing the actual product, explaining a
workflow, establishing a place, or providing clearly illustrative atmosphere.

- Prefer usable supplied images or real product captures when they show the
  intended subject. Owning a file is not, by itself, evidence of reuse rights.
- If an available image tool suits the request, follow its workflow. Generated
  media must not impersonate the client's real people, premises, inventory, or
  product evidence. Do not replace a required real photograph with invented proof.
- Search outside sources only when authorized and useful. Verify each candidate
  at its source page; a search preview, direct image URL, or repository license
  does not establish the rights to a particular embedded photograph.
- If suitable material is missing or reuse is uncertain, choose a finished
  typographic composition, an original relevant illustration, or an honest
  product fragment permitted by the brief. In a complete deliverable, do not
  leave broken images or fake product shots. Temporary placeholders belong only
  in an explicitly provisional mockup and must be identified as such.

Do not add images, video, network requests, or an image-generation step to meet
a quantity target. A small restyle need not source any new assets. Ask for an
asset only when its absence materially blocks the requested result.

## Keep an asset-level record

For each externally sourced asset actually reused, retain the following in the
project's existing asset/provenance mechanism, or the delivery notes when there
is none. Do not create a new standalone document by habit.

| Field | What to record |
| --- | --- |
| Local file and use | File path, placement, and whether it is actual product evidence or illustration |
| Source | Original item page and identifier, not only the CDN URL; date checked |
| Creator and rights | Creator as supplied, license/permission statement and its source; unknown stays unknown |
| Credit | The required wording/link and where it appears, following the supplied terms and project policy |
| Changes | Crop, recoloring, compositing, or other material modifications |

For supplied files, retain the provided permission/provenance rather than
inventing an author or license. For generated assets, identify that origin and
record the relevant creation reference when available. Do not fabricate a
license, claim permission was verified without checking, or treat attribution
alone as permission. If the terms conflict with the intended use, select a
suitable alternative or raise that concrete dependency.

## Compose and verify

- Pick crop and focal point for both wide and narrow layouts. Check the actual
  subject remains visible, aspect ratio is preserved, and overlaid text reads.
- Supply meaningful alt text for informative images and empty alt for decorative
  ones. Do not use alt text to invent facts or duplicate nearby content.
- Size media for its placement, reserve layout space, and use the project's
  responsive-image/loading conventions. Keep important first-screen content
  available when media is slow, blocked, or fails.
- Inspect the rendered result and the source/credit record. A passing image-load
  check proves neither visual suitability nor reuse rights.
